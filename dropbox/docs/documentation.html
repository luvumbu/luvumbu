PhotoSync — Documentation

Sauvegarde automatique des photos et vidéos d'un téléphone Android vers votre propre serveur PHP/MySQL, avec comptes utilisateurs, galerie web protégée, corbeille 30 jours et envoi manuel depuis iPhone / navigateur.

Android (Kotlin) PHP 7.4+ / MySQL Multi-comptes https://luvumbu.com

§À propos

PhotoSync est composé de deux moitiés qui dialoguent en HTTP / JSON + multipart : une application Android qui envoie les médias en arrière-plan, et un serveur PHP qui les reçoit, les range et les sert. Chaque utilisateur possède un compte et ne voit que ses propres photos.

Adresse du serveur

luvumbu.com — à la racine, sans sous-dossier.

Code d'inscription

Le mot de passe de la base de données (DB_PASS) sert de code pour créer un compte.

§Architecture générale

│   App Android (Kotlin)  │ ──────────────────►  │   Serveur PHP (mutualisé)    │
│  WorkManager (15 min)   │  multipart / JSON     │  api/*.php  → JSON            │
│  OkHttp · Room · Coil   │ ◄──────────────────   │  web/*.php  → pages HTML     │
└─────────────────────────┘   jeton X-Auth-Token  │  uploads/   → fichiers       │
            ▲                                      │  MySQL      → métadonnées    │
            │                                      └──────────────────────────────┘
   Navigateur (iPhone/PC) ── session web (cookie) ──────────┘
  • Serveur : PHP 7.4+ avec PDO MySQL, sans framework. api/ (machine), web/ (navigateur), lib/ (code commun).
  • Client Android : minSdk 26 / targetSdk 35, synchro via WorkManager.
  • Cloisonnement : chaque requête est filtrée par user_id ; jeton de 64 caractères hex par compte (en-tête X-Auth-Token).

1Android — premier démarrage

Installer l'application

  1. Copiez PhotoSync.apk (ou apk.apk) sur le téléphone et ouvrez-le.
  2. Autorisez l'installation depuis cette source (avertissement normal hors store).
  3. Installez et ouvrez PhotoSync.

Créer son compte

  1. Saisissez le domaine luvumbu.com (cochez « sous-dossier » seulement si nécessaire).
  2. Choisissez Créer un compte : identifiant (3–64 car.), mot de passe (≥ 4 car.).
  3. Entrez le code d'inscription = mot de passe de la base de données du serveur.
  4. Acceptez l'accès aux photos et vidéos à la première synchro.
💡 Le tout premier compte créé récupère les photos envoyées avant la mise en place des comptes.

Ce qui se passe pendant une synchro

  1. 🔍 Vérification — le serveur indique ce qui est déjà sauvegardé (pas de réenvoi).

⚙️ Fiabilité : Réglages → Applications → PhotoSync → Batterie → Sans restriction, pour que la synchro en arrière-plan ne soit pas coupée.

8Renvoi des fichiers — flux d'upload

C'est le cœur du système : parcours complet d'une photo, du téléphone au disque serveur.

① Côté Android — UploadWorker.doWork()

1. isLoggedIn ?                       → sinon « Compte non connecté »
2. (1ʳᵉ fois) verifySetup() :         permission photos + api/setup.php (compte/schéma/espace)
3. SCAN local  : MediaScanner         images + vidéos (MediaStore), du + ancien au + récent
4. FILTRE      : retire les ids déjà présents dans Room (base locale)
5. VÉRIF       : api/names.php         noms déjà sur le serveur → ignorés (comptés "skipped")
6. ENVOI       : Semaphore = 4         envois EN PARALLÈLE, limités par maxPerSync
                   api.upload(photo) → succès = markUploaded immédiat (reprise possible)
                   échec : si 0 réussie et ≥3 échecs → abandon (serveur KO)
7. BILAN       : notification « ✅ X sauvegardée(s) » ; que des échecs → Result.retry()
Deux niveaux d'anti-doublon côté client : base Room (id MediaStore) + noms serveur (names.php). Le SHA-256 reste le filet de sécurité côté serveur.

② Côté Android — ApiClient.upload()

// content:// n'est pas un fichier : copie d'abord dans le cache
val tmp = File.createTempFile("up_", ".bin", cacheDir)
contentResolver.openInputStream(photo.uri).copyTo(tmp)

MultipartBody.FORM
  .addFormDataPart("taken_at", photo.dateTakenMs.toString())
  .addFormDataPart("photo", photo.name, tmp.asRequestBody(mime))

POST {serverUrl}/api/upload.php
   header X-Auth-Token: <jeton>
finally { tmp.delete() }   // toujours nettoyé

Timeouts OkHttp adaptés aux gros médias : connect 30 s, write 20 min, read 5 min.

③ Côté serveur — api/upload.php

1. POST requis (sinon 405)
2. uid = currentUserId() (jeton OU session web), sinon 401
3. $_FILES['photo'] OK ? sinon 400
4. contrôles : taille > 0 · MAX_BYTES (0=illimité, sinon 413) · is_uploaded_file()
5. sha = hash_file('sha256', tmp)
6. DÉDUP   : SELECT WHERE user_id=uid AND sha256=sha → {duplicate:true} sans réécrire
7. RANGE   : uploads/<uid>/<AAAA>/<MM>/<sha12>_<nom assaini>
8. move_uploaded_file(tmp, dest), sinon 500
9. INSERT (user_id, sha256, original_name, stored_path, size_bytes, taken_at)
10. réponse 201 {ok:true, duplicate:false, path}
Même si l'app envoyait un doublon, le serveur le détecte par contenu (SHA-256) et ne stocke jamais deux fois.

media.php — sert une image au propriétaire

  • Auth : session web ou jeton ; l'admin voit tout.
  • Anti-traversal : realpath() doit rester sous uploads/.
  • Auto-nettoyage : fichier disparu → entrée supprimée + 404 (plus d'image cassée).
  • Vignette : image → cache JPEG via GD (500 px, qualité 82) ; vidéo → icône SVG « ▶ ».

Corbeille (lib/Photos.php)

trash / restore / deleteForever / purgeOldTrash (suppression après TRASH_DAYS = 30 jours). Toujours scopé au compte.

10Sécurité

  • Fichiers privés : uploads/.htaccess (Require all denied, php_flag engine off) → tout passe par media.php.
  • Cloisonnement : filtrage user_id partout + index (user_id, sha256).
  • Mots de passe : password_hash() / password_verify(), temps constant.
  • Upload : is_uploaded_file(), nom assaini, taille bornée.
  • Sessions : session_regenerate_id(true) à la connexion.
🔐 Après l'installation, supprimez install.php : il n'est pas protégé par mot de passe.

12Installer le serveur

Prérequis

PHP 7.4+ avec pdo_mysql et gd · une base MySQL + utilisateur · accès FTP.

  1. Base de données : créer base + utilisateur dans le panneau de l'hébergeur ; noter nom / utilisateur / mot de passe.
  2. Envoyer les fichiers : déposer le contenu de public_html/ (et non le dossier) directement à la racine → on obtient public_html/api/, public_html/lib/, etc.
  3. Assistant : ouvrir https://luvumbu.com/install.php → formulaire (hôte, base, utilisateur, mot de passe, préfixe) → Enregistrer et vérifier. L'assistant écrit lib/db.config.php, crée les tables et uploads/, et affiche un rapport vert.
  4. Sécuriser : supprimer install.php. La config reste dans db.config.php.
  5. Régler config.php si besoin : GALLERY_PASSWORD, MAX_BYTES (0 = illimité).
L'assistant peut créer la base lui-même (CREATE DATABASE IF NOT EXISTS) si l'hébergeur l'autorise. En local XAMPP : hôte localhost, user root, mot de passe vide.
